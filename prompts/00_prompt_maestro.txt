Lee completamente @documentos/ y @AGENTS.md.

Tu tarea es construir el proyecto completo de un sistema empresarial de inventario para una distribuidora de pollos asados y apanados, modelando todo el flujo del negocio de forma coherente, usable y profesional.

FUENTE DE VERDAD OBLIGATORIA
La carpeta /documentos contiene:
- la tabla de requisitos funcionales
- el SQL completo de la base de datos PostgreSQL

Debes usar esos documentos como base principal y mantener consistencia total entre requisitos, modelo de datos, backend, frontend, documentación y pruebas.

OBJETIVO GENERAL
Construir el proyecto completo con:
1. backend dockerizado
2. frontend usable y conectado al backend
3. documentación profesional
4. colección Postman JSON
5. estructura limpia y mantenible

INSTRUCCIONES IMPORTANTES DE IMPLEMENTACIÓN
1. Primero analiza la carpeta /documentos y resume:
   - módulos del sistema
   - entidades principales
   - relaciones
   - flujos críticos
   - endpoints esperados
   - riesgos de implementación

2. Después genera un plan técnico completo antes de escribir código.
   No empieces a programar hasta presentar ese plan.

3. El plan debe incluir:
   - arquitectura del backend
   - estructura de carpetas del backend
   - estructura de carpetas del frontend
   - módulos del sistema
   - estrategia de seguridad JWT
   - estrategia de persistencia
   - mapeo entre requisitos y módulos
   - lista de endpoints por módulo
   - estrategia de pruebas
   - estrategia de Docker
   - estrategia de documentación

4. Una vez aprobado el plan, construye el backend en /backend.
5. Usa el SQL de /documentos como referencia obligatoria del esquema de base de datos.
6. Después construye el frontend en /frontend.
7. Solo después de backend y frontend, construye las pruebas.
8. Debes crear:
   - README.md profesional del proyecto
   - README-ENDPOINTS.md con resumen y detalle de endpoints
   - archivo JSON de colección Postman en /postman
   - README de Postman explicando cómo importarlo y probarlo
